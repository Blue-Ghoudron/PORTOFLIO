# Portfolio test plan — spec

Beads epic: `pf-qsm` (`bd list --parent pf-qsm`). Written 20.10.2026.

## Why
The site is shown to people who might hire the photographer. Broken links, a crash on a phone, or a page that loads slowly cost more than they would on a hobby site. Today every check is a one-off script that disappears with the session, so the same bugs come back. The plan turns checks into tasks with clear results, then into fixes.

## Goals
- A saved click-through test that one command runs (`pf-qsm.1`).
- Find what to improve: bugs, accessibility, phones, other browsers, speed, content, design.
- The user **sees** every change: before/after screenshots side by side (`pf-qsm.19`).
- A design critique, then a redesign of only what the user approves (`pf-qsm.17` → `pf-qsm.18`).

## Non-goals
- No CI service and no test framework install beyond Playwright (already on the machine) and axe-core / Lighthouse run on demand.
- Agents don't fix things themselves.

## Who runs what
- **`agent` label** (14 tasks): a parallel subagent, named after its task (`pf-qsm.N <title>`). Read-only on the site. It writes only `tests/pf-qsm.N_*.py` and a report with screenshots. Each problem it finds becomes a new beads task under `pf-qsm` that depends on nothing and is labelled `main`.
- **`main` label** (5 tasks): done in the main session, because they edit the site or need the user's approval.
- All fixes go on the branch `Portoflio-Fixes`, one commit per fix, with the beads id in the message. Close the task with `bd close <id>` once its test passes.

## Done when
- `tests/flow.py` passes at 390 / 820 / 1440 px in Chromium, Firefox and WebKit.
- No serious accessibility violations; no broken links or images; LCP under 2.5 s on a mid-range phone profile, or the fixes are listed as tasks.
- The user has seen before/after for every redesign change and approved it.
